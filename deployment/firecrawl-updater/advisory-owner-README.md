# Firecrawl advisory scan owner — review required

This independent owner refreshes the pinned Trivy vulnerability DB in an isolated temporary writable cache, checks its schema and UTC timestamps, and atomically promotes a private generation only after validation. Freshness requires `NextUpdate` in the future, `UpdatedAt` no older than 48 hours, and consistent non-future timestamps. Refresh errors or stale/malformed DB metadata fail the run; an older cache is never silently substituted. The refresh contacts Trivy's DB registry, but does not receive images, Docker credentials or a Docker socket. There is no network notification or report transmission.

The owner copies the promoted DB to a private temporary scan cache, captures all three running API container/image IDs, runs each image scan with `--network=none`, `--skip-db-update`, and `--offline-scan`, then rechecks all three container identities. It atomically writes `~/.local/state/firecrawl-advisory/reports/latest.json` mode 0600. A failure publishes an error report instead of a previous clean result; if writing the report itself fails, the process exits 2 and the previous file can remain. Exit 0 means no HIGH/CRITICAL findings, 1 means findings, and 2 means incomplete/error. `SuccessExitStatus=1` keeps findings distinct from service failure; inspect the private report for findings.

The scan does not download the much larger Java DB. A detected Java result causes an incomplete error, and Trivy itself can fail when a Java DB is required. Coverage of Java artifacts without an identified Java result is not guaranteed; this owner is intended for the observed Firecrawl Node images, not a general Java scanner. DB metadata freshness does not independently establish feed authenticity or completeness. The archive identity verification relies on Docker export and does not independently verify every layer. Running containers can change after the final check.

Persistent cache generations are private under `~/.local/state/firecrawl-advisory/cache/generations`; `current` is atomically switched, and only the new generation and the previously verified current generation are retained. Deletion accepts only owner-marked, private generations with the exact expected files and never follows symlinks. Unknown entries are left untouched; malformed generation entries fail the scan. Interrupted temporary refresh directories are not automatically removed and may require manual inspection. The three API images are scanned separately, even if findings overlap. A lock prevents overlapping scans; lock contention exits 2 without replacing the active run's report. DB refresh and scan can consume network bandwidth, CPU, memory and disk. No updater timer, deployment or service is changed by the owner.

The service and daily timer are separate from the six-hour updater timer. `install-advisory.sh` installs files only, refuses existing files and does not reload, enable or start anything. Review account, Docker access, filesystem capacity, DB update/retention, monitoring of exit 2, Java coverage and timers before installation.

Tests: `python -B -m unittest discover -s deployment/firecrawl-updater -p 'test_advisory*.py'`. POSIX-specific permission and atomic-promotion tests require Linux.
